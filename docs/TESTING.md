### Plan 03 live probe (0.6.0)

Recorded on **October 5, 2026 (America/New_York)** on macOS **27.0.1 (26A434)**, iCloud account, with `--synthetic-fields-probe` from a build signed with the installed app's local identity: **34 of 34 steps passed**, and the four probe collections were removed and their absence verified after every run. Earlier runs of the same probe found five EventKit behaviors that the offline tests couldn't, each now handled in the core and covered by a unit test:

| Behavior observed | Handling |
| --- | --- |
| An event's location text and map pin are one value: setting the text after a pin replaces the pin; the text is always the pin's title. | A `location` sent with `structuredLocation` must equal its title; the pin is written alone. |
| All-day events are always floating: `isAllDay` clears the zone, and setting a zone afterwards makes the event timed. Their dates are read in the Mac's zone. | All-day writes save the requested dates as midnights in the Mac's zone, without a zone. (0.5 would have saved a Kolkata all-day event a day early from a New York Mac.) |
| An all-day `endDate` is read as a moment inside the last day; the exclusive midnight adds a day. | The end is written as 23:59:59 on the last day; readbacks compare calendar days. |
| iCloud gives an occurrence changed on its own a new ID, `<series>/RID=<n>`. | Rows report the series ID; lookups accept both. |
| `EKReminder.location` can't be set (the setter is a no-op); a due day is kept floating and a start day becomes floating midnight. | Reminder location text is read only; due and start days are compared by date. |

Spike results on this account: **S1** the requested zone is kept exactly (`Europe/Madrid`, `Asia/Calcutta`), all-day events have none. **S2** a `future` split gives the new series a new event ID; moving an event or a reminder within the account keeps its ID. **Q3** map pins (coordinates and radius) are kept. **S4** (this Mac) a reminder's URL and priority are stored; its location text can't be. **Q5** relative reminder alarms stay relative. **S5** (storage only) location alarms on events and reminders are stored; delivery on a device isn't established. **S6** (this Mac) one occurrence of a daily, timed, alarm-free iCloud reminder was completed through the bridge with the account-type allowlist, and the transition verified. iCloud drops alarm sounds. Calendars on this account accept availability `busy` and `free`.

The same day, `--synthetic-phone-stage` left three synthetic items for the owner to check on an iPhone, then `--synthetic-fields-cleanup` removed them and verified their absence. **S4**: the Reminders app shows a reminder's priority, notes and location alert, but **not its URL** (stored and readable by agents only). **S5**: the event's and the reminder's location alerts appear on the iPhone; whether they fire on arrival or departure wasn't tested. **S6**: one occurrence of a daily reminder completed through the bridge showed on the iPhone as exactly one completed copy and the series advanced to the next day. **S1/Q3**: a weekly event saved in Europe/Madrid showed at the right local time, with its map, link, notes and alerts. **S3** (what attendees receive from organizer edits) remains open: EventKit can't create attendees, so it needs a real invitation the owner organizes.

The ordinary source build has no persistent installation, privacy grants, login registration, or client credential. The installed Mac's local configuration is evidence for that machine only.

### Release install test

Run it before the first public release and after any change to the bundle layout or the updater, and record the date, macOS version and architecture here.

**October 6, 2026:** the owner installed the notarized 0.7.0 rehearsal DMG on a separate Mac; it opened without warnings and everything worked (steps 1–3). Step 4, installing over it, is covered by the [update test](#update-test) with Sparkle; step 5 wasn't run (no Intel Mac).

5. If an Intel Mac is available, repeat steps 1–3 there: the `x86_64` slices are compiled and checked but have never run.

## Write journal persist time (§9.7 of the MCP plan)

Measured by `Tests/WriteJournalQuotaTests.swift` on the development Mac with 10,000 completed entries at the default caps. In one file (5.9 MB), each fsynced rewrite took about 60–70 ms, over the plan's 50 ms limit, so the journal is sharded by client (`write-journal/<client>.json`): with the entries spread over six clients, a write's `begin` + `finish` (two rewrites of one shard) has a median of about 57 ms, about 28 ms per rewrite. The test prints the current number on every run. It runs up to three rounds and keeps the best median. A median over the 100 ms budget only prints a warning, because a busy or swapping Mac can be several times slower; it fails at 500 ms, which catches regressions such as rewriting every shard per write. To enforce the budget, run on an idle Mac with `EVENTKIT_STRICT_TIMING=1 sh test.sh`.

## Troubleshooting

| Symptom | Read-only checks and next step |
| --- | --- |
| No menu bar icon | Check whether the installed app launched in the current logged-in GUI session. Inspect macOS Login Items status if Launch at Login was expected. Do not start a second copy while one is running. |
| CLI exits 3: `isn't running, or the bridge is off` or `the bridge session changed` | Check the menu bar icon (a check mark means on) or Overview; confirm the app is running and the bridge is on. Check that `client.py` uses the matching `bridge-client` (`sh build.sh`). A stale `/tmp` descriptor after a crash is not proof that the bridge is active. Exit 4 means a missing or unsafe key, parameter or registry file; the message names the file. |
| `forbidden` | Select the row in Activity: it names the client, the calendar or list, and the missing access, with a button to that row. Confirm the exact Calendar or Reminders ID and the client's saved action boxes. Names can repeat; a Read grant does not imply Create, and vice versa. |
| `full_access_required` | Check Overview ▸ macOS access (the menu bar icon also shows an exclamation badge) and macOS Privacy & Security settings for the installed signed app. A differently signed or relocated build may be treated differently. Do not reset TCC blindly. |
| `conflict`, `item_unavailable`, or `occurrence_conflict` | Read the item again and use its current ID, version, due instant, and fingerprint. Provider sync can change them. |
| `idempotency_pending_review`, `completion_readback_uncertain`, `journal_clock_rollback`, or timeout after a write | Stop automatic retries. Inspect the exact item and journal state locally with appropriate authorization; reconcile whether the write happened before sending any new key. Never delete the journal merely to clear a failure. |
| Recurring completion is `recurrence_shape_unsupported` | Check the [exact supported shape](API.md#reminder-schedules) and whether a verified local source pin exists. The repository default intentionally disables this path. Do not clear a real item's recurrence to bypass the guard. |
| An AI agent can't connect, or its calls fail | Run `bridge-mcp check --client <client ID>` with the launcher path from Settings ▸ MCP Server; it reports the token file, server, token, visible tools and bridge state without printing the token. See [MCP troubleshooting](MCP.md#troubleshooting) for each message. |
| A cloud agent can't connect | Click **Test** in Settings ▸ Remote Access; it says whether the tunnel, DNS or `Host` is the problem. See [MCP troubleshooting](MCP.md#troubleshooting) for the remote messages. Check Activity with the **Remote Access** filter: a refused request with a cloud icon reached the app. |
| The window behaves oddly | Use the installed build; `MainWindowController` keeps the window across close and reopen, and `sh ui_test.sh` covers close/reopen with sheets in isolation. If a new crash appears, compare the crash report's executable UUID with the installed binary before attributing a fixture crash to the installed app. Avoid publishing raw crash reports containing local paths. |

When investigating, prefer a disposable client and app-owned empty test collections. A user must approve any live Calendar or Reminders mutation. Keep credentials, MCP and remote tokens, OAuth client secrets, Remote Access URLs with their secret path, agent configs containing tokens, personal titles, full activity records, and raw response files out of issues and commits.
